MASTER'S PROJECT THESIS · OTH REGENSBURG · GRADE 1.3

Automated CAL Inheritance across the ASPICE V-Model

Cybersecurity Assurance Level (CAL) propagation in Codebeamer ALM, implemented in a live automotive customer project during my cybersecurity internship at Minebea AccessSolutions. A CAL assigned from the threat analysis now follows the trace links from stakeholder requirements down to software detailed design.

Codebeamer ALM ISO/SAE 21434 ASPICE V-Model TARA UEL Computed Fields Traceability
THE PROBLEM

One CAL value, six layers of requirements

Under ISO/SAE 21434, a CAL is determined from the threat analysis and risk assessment (TARA), based on impact and attack vector. It sets how rigorously everything derived from that requirement must be developed and tested.

Maintained by hand, the value has to be re-entered at every level of the V-model. A requirement rated CAL 3 can end up as CAL 1 two layers further down, and the mismatch only surfaces in an audit.

APPROACH

Let the trace links carry the CAL

The CAL is entered once, at stakeholder level. Every tracker below it reads the value from its linked upstream items instead of storing its own.

01 Stakeholder RequirementsCAL set from TARA: choice list CAL-1 to CAL-4, or No CAL
02 System RequirementsInherited from stakeholder requirements or cybersecurity goals
03 System ArchitectureComputed from the linked system requirement
04 SW RequirementsHighest CAL across all linked upstream items
05 SW ArchitectureConsolidates upstream values, with fallback
06 SW Detailed DesignMapped from SW architecture
IMPLEMENTATION

What I configured in Codebeamer

01 · FIELD

Custom CAL field

A shared choice list (CAL-1 to CAL-4, No CAL) added to the stakeholder requirements tracker, reusable across trackers.

02 · LINKS

Intermediate reference fields

Reference fields connecting each tracker to its upstream layer, including a goals-and-claims tracker that justifies each CAL.

03 · LOGIC

Computed fields in UEL

CAL fields written as User Expression Language computations, so upstream changes appear downstream without manual edits.

04 · RULE

Highest CAL wins

Where an item links to several upstream sources, a max() rule over the linked artifacts keeps the most demanding CAL.

RESULT

One value, entered once, carried through

Reviewing a sample trace chain, a CAL 4 assigned to a stakeholder requirement reached all five downstream layers unchanged, and each value could be traced back to the requirement it came from.

6 layersStakeholder requirements to SW detailed design
CAL 4Carried end-to-end on the sample chain
1 entryManual input only at stakeholder level
LIMITS & NEXT STEPS

Inheritance is only as good as the links

If a requirement is not linked to its parent, its CAL is not inherited, and nothing warns about it. The next steps proposed in the thesis were automated link checks that flag orphaned items, and synchronising CAL values with the TARA tool so risk ratings and requirements stay aligned.
