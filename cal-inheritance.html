Cybersecurity Assurance Level (CAL) Inheritance in Codebeamer

Carried out during my automotive cybersecurity internship at Minebea AccessSolutions (Jul – Oct 2024): correcting and extending how CAL values are inherited and derived across linked requirements in Codebeamer ALM, in line with ISO/SAE 21434.

Codebeamer ALM Automotive Cybersecurity ISO/SAE 21434 TARA Traceability
THE PROBLEM

One CAL value, many linked artifacts

A Cybersecurity Assurance Level is assigned from the threat analysis and risk assessment (TARA) and has to stay consistent as requirements are refined from stakeholder level down to system and software level.

In the project's Codebeamer setup, the existing CAL field and its inheritance did not carry values reliably, and the system trackers had no CAL field at all. Keeping the values aligned meant entering them by hand at each level.

APPROACH

Following the existing trace links

Instead of adding a separate mechanism, the work used the reference links that already connect requirements in Codebeamer. A CAL value set at the top of the chain could then be read by every linked item below it.

01CAL assigned from TARA
02Stakeholder requirements
03System requirements
04Downstream system and software items
IMPLEMENTATION

What I changed in Codebeamer

01 · CORRECT

CAL field and inheritance

Fixed the existing CAL field and its inheritance so values flow correctly along the reference links.

02 · EXTEND

System trackers

Added a CAL field to the system trackers, with computed derivation from the linked higher-level items.

Custom fields Computed fields Reference links Tracker configuration
RESULT

Change it once, see it everywhere

A change to the originating CAL value now shows up in the linked items instead of being maintained separately at every level, and each value can be traced back to the cybersecurity assessment it came from.

ENGINEERING TAKEAWAY

Cybersecurity decisions as traceable engineering data

The main lesson was not storing a CAL value but understanding how it moves through the development structure, and letting the tool keep that relationship instead of people.
